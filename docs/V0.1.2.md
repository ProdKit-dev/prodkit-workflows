# ProdKit Workflows v0.1.2

`v0.1.2` adds a reusable exact-main post-gate branch-cleanup authorization path while preserving the `v0.1.1` explicit `workflow_dispatch` cleanup boundary and its existing deletion engine.

## Outcome

Consumers can keep one permanent cleanup surface instead of creating temporary `workflow_run` closers for each release or maintenance cycle.

The lifecycle becomes:

`exact-main gate completion -> Post-Gate Branch Cleanup authorization -> dispatch-only Branch Cleanup -> existing SHA-bound cleanup engine`.

The post-gate workflow never deletes a Git ref itself. It owns only gate verification and bounded dispatch. Destructive branch validation and deletion remain centralized in `reusable-branch-cleanup.yml`.

## Exact-main gated cleanup

`reusable-gated-branch-cleanup.yml` accepts:

- an explicit reviewed JSON list of branch names;
- the exact default-branch SHA from the triggering `workflow_run`;
- a non-empty JSON list of required exact-SHA push workflow gates;
- the dispatch-only Branch Cleanup workflow filename;
- a direct `runner_json` target.

The reusable authorization workflow requires a `workflow_run` originating from a `push` on the repository default branch. It verifies that the trigger SHA still equals the current default-branch SHA, validates the target cleanup workflow is `workflow_dispatch` only, and verifies each required gate by immutable workflow path and exact source SHA.

Missing or still-running gates defer without mutation. A completed non-success required gate fails closed. When every required gate is green, only the last completed required gate event is permitted to dispatch cleanup, preventing the normal CI/Security/CodeQL completion fan-out from creating duplicate cleanup requests.

Immediately before dispatch, the workflow rereads the default branch and requires it to remain on the exact reviewed SHA.

## Exact-SHA handoff to the manual cleanup boundary

The generated `branch-cleanup.yml` remains `workflow_dispatch` only. `v0.1.2` adds an optional `expected_default_sha` input.

Manual operators may leave it empty, preserving the existing behavior of binding cleanup to `${{ github.sha }}` at dispatch time. The gated workflow supplies the exact SHA it certified. If the default branch moves after gate verification but before the dispatched cleanup run begins, `reusable-branch-cleanup.yml` rejects the request before deletion.

This closes the authorization-to-dispatch race without weakening the dispatch-only deletion contract.

## Permanent dormant caller

Bootstrap now installs `post-gate-branch-cleanup.yml` alongside `branch-cleanup.yml`.

The caller is dormant until the repository variable `PRODKIT_GATED_CLEANUP_BRANCHES_JSON` contains a non-empty JSON array of exact reviewed branch names. By default it listens for `CI`, `Security`, and `CodeQL` workflow completions and requires exact-SHA CI and Security push runs.

`PRODKIT_GATED_CLEANUP_GATES_JSON` may override the required gate set with explicit `{name,path}` objects. If a repository adds another required gate, its workflow name must also be present in the caller's `workflow_run.workflows` list so the last required gate completion can authorize dispatch.

The caller grants `actions: write` only to the authorization job so it can dispatch the permanent Branch Cleanup workflow. It retains `contents: read` and does not grant `contents: write`; the authorization layer cannot delete branches directly.

## Evidence and failure semantics

The gated workflow writes structured evidence to its job output and Actions summary, including:

- repository and default branch;
- exact reviewed SHA;
- triggering workflow run ID;
- required gate names, paths, run IDs, status, conclusion, and update time;
- requested branch count;
- cleanup workflow identity;
- authorization state such as `deferred`, `gate_failed`, `not_final_gate`, `stale_trigger`, or `dispatched`.

Actual deletion evidence remains produced by `reusable-branch-cleanup.yml`, which retains the complete v0.1.1 safety model: explicit names only, full-set preflight, default/protected/open-PR rejection, exact target-SHA revalidation before every delete, repeated default-SHA checks, serialized mutation, idempotent already-absent handling, and post-delete absence verification.

## Bootstrap and organization governance

`bootstrap_consumer.py` now installs both cleanup callers. Organization audit requires both callers at one reviewed immutable `prodkit-workflows` SHA and verifies that:

- `branch-cleanup.yml` remains `workflow_dispatch` only;
- `post-gate-branch-cleanup.yml` remains `workflow_run` only;
- the post-gate caller is dormant unless the reviewed branch-list variable is populated;
- the post-gate caller uses exact `workflow_run.head_sha` handoff;
- only the post-gate authorization job receives `actions: write`;
- the post-gate caller does not receive `contents: write` and therefore cannot implement deletion locally.

Regression tests lock the same topology and reject direct deletion logic in the gated reusable workflow.

## Compatibility and versioning

`v0.1.2` is additive. Consumers pinned to `v0.1.1` keep the existing dispatch-only Branch Cleanup unchanged. Consumers adopting `v0.1.2` should repin the complete generated workflow family to the exact `v0.1.2` release commit SHA.

The immutable `v0.1.0` and `v0.1.1` releases remain unchanged.
