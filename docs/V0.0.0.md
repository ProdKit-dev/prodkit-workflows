# ProdKit Workflows v0.0.0

Initial organization workflow control plane.

This release establishes compact-default and expanded-compatible reusable CI/Security orchestration, exact-SHA guarded GitHub Releases, immutable tags, SPDX SBOM generation, provenance attestations, draft-first checksum-verified publication, guarded metadata-only repair for already-published Releases, consumer bootstrap contracts, importable organization rulesets, and organization-wide workflow drift auditing.

The final runner contract is deterministic: callers pass the reusable workload a complete `runner_json` target directly. Generated trusted workloads default to `["self-hosted","Linux","X64"]`; a repository may provide `PRODKIT_RUNNER_JSON` as the complete replacement JSON value. Fork-originated CI/Security pull requests are forced to GitHub-hosted execution. New callers do not add a hosted availability probe, runner resolver, destructive workspace-preflight controller, or automatic runner switching. `reusable-runner-policy.yml` remains available only for consumers already pinned to earlier revisions.

Generated consumers use compact CI and Security by default. Enabled Python/Node compatibility dimensions, PostgreSQL acceptance, custom checks, Gitleaks, dependency audits, container scanning, SBOM generation, and evidence handling execute as steps inside the stable `CI Required` or `Security Required` job rather than as a large set of independent GitHub jobs. Intermediate contract steps may continue after failure solely to collect complete evidence; the final verifier aggregates every enabled outcome and fails closed. Stable branch-protection identities remain `ci / CI Required` and `security / Security Required`.

The expanded `reusable-ci.yml` and `reusable-security.yml` remain available for already-pinned consumers and repositories that deliberately prefer independent parallel matrices. Compact CI supports Python 3.12/3.13/3.14 and Node 20/22/24 and rejects unsupported or duplicate version selections.

Release proof/publication also use deterministic current-main identity. `Trusted Release Proof` is explicitly dispatched and certifies `${{ github.sha }}` rather than accepting a manually copied source SHA. The generated Release caller publishes `${{ github.sha }}` rather than accepting a manually copied target SHA, first verifies a successful dispatched proof for that exact SHA, then calls `reusable-release.yml` directly. The guarded publisher independently requires successful exact-SHA main CI/Security evidence. `reusable-release-pipeline.yml` remains only for backward compatibility with older pinned consumers.

CI/Security adapter paths are runtime-contained beneath `.prodkit/workflows/`; full-history Gitleaks produces redacted evidence and supports reviewed repository-contained allowlists; release-manifest v1 is strictly shape-validated; and consumer release output is rejected if empty, nested, symlinked, or colliding with central-owned evidence names.

Release publication and release-presentation repair have separate trust boundaries. Publication owns immutable source/payload creation and remote verification. Metadata repair is valid only for an already-published immutable tag and may reconcile canonical Release `name` and `body` only after verifying the tag and full published checksum set; it then re-verifies immutable source/payload identity.

The generated consumer lifecycle contains five required callers: CI, Security, Trusted Release Proof, Release, and Release Metadata. Organization audit validates all five against the direct reusable workflow family at the required immutable SHA and rejects retired runner-controller usage. CodeQL remains opt-in.

The workflow surface is intentionally layered: reusable implementations remain centralized while caller execution stays thin and deterministic. The key invariant is that `prodkit-workflows` supplies workloads, not a second scheduler layered on top of GitHub Actions.
