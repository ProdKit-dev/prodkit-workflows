# ProdKit Workflows v0.0.0

Initial organization workflow control plane.

This release establishes reusable CI and Security matrices, exact-SHA guarded GitHub Releases, immutable tags, SPDX SBOM generation, provenance attestations, draft-first checksum-verified publication, guarded metadata-only repair for already-published Releases, consumer bootstrap contracts, importable organization rulesets, and organization-wide workflow drift auditing.

The final v0.0.0 contract supports both GitHub-hosted and trusted self-hosted execution through one condition-driven runner policy. GitHub-hosted Ubuntu remains the fail-safe default; `PRODKIT_RUNNER_MODE` may select GitHub-hosted or self-hosted execution at organization/repository level, manual dispatch can override the policy, and fork-originated pull requests are always forced onto GitHub-hosted runners. GitHub Actions has no native ordered hosted-to-self-hosted fallback, so automatic quota/capacity detection still requires a trusted controller or explicit redispatch.

CI and Security adapter paths are runtime-contained beneath `.prodkit/workflows/`; full-history Gitleaks produces redacted evidence and supports repository-contained reviewed allowlists; release-manifest v1 is strictly shape-validated; and consumer release output is rejected if it is empty, nested, symlinked, or attempts to overwrite central proof/source/SBOM artifacts. Contract tests lock these guarantees to `docs/CONTRACTS.md`, bootstrap output, local validators, and reusable workflow behavior.

Release publication and release-presentation repair have deliberately separate trust boundaries. Publication requires the requested source SHA to be current `main` with successful exact-SHA CI/Security evidence and owns tag/artifact creation. Metadata repair is valid only for an already-published immutable tag: it uses current `main` solely as the canonical title/notes source, proves the tag still resolves to the supplied historical source SHA, verifies the complete published checksum set, changes only GitHub Release `name` and `body`, and re-verifies that tag identity, publication flags, asset identity, and payload checksums are unchanged.

The workflow surface is intentionally layered rather than one-to-one: `.github/workflows/` contains 9 YAML files (4 operator-facing workflows plus 5 reusable implementations), the generated consumer adapter catalog contains 11 shell adapters, and this control-plane repository itself enables only 4 `.prodkit/workflows/` adapters. Disabled capabilities do not require local adapter files; enabling a capability makes its configured adapter mandatory and runtime-validated.
