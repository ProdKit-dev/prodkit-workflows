# ProdKit Workflows v0.0.0

Initial organization workflow control plane.

This release establishes reusable CI and Security matrices, exact-SHA guarded GitHub Releases, immutable tags, SPDX SBOM generation, provenance attestations, draft-first checksum-verified publication, guarded metadata-only repair for already-published Releases, consumer bootstrap contracts, importable organization rulesets, organization-wide workflow drift auditing, and hosted-first automatic runner failover.

The final v0.0.0 runner contract supports GitHub-hosted and trusted self-hosted execution through one condition-driven policy. `PRODKIT_RUNNER_MODE=auto` and an unset policy perform a minimal repository-code-free, non-poisoning `ubuntu-latest` availability probe before trusted workloads. The probe emits `available=true` only when a hosted runner actually starts; when that positive output is absent under auto policy, the unchanged reusable workflow is routed to `["self-hosted","Linux","X64"]`. `continue-on-error: true` prevents the infrastructure probe itself from poisoning an otherwise successful fallback workflow. Explicit `github-hosted` and `self-hosted` modes remain strict operator choices, manual dispatch can force `auto`, and fork-originated pull requests are always forced onto GitHub-hosted runners. Failover happens before product validation or release steps, so genuine test/security/publication failures never cause retry on another runner. Indefinitely queued hosted jobs and complete GitHub Actions control-plane outages remain outside in-workflow failover.

CI and Security adapter paths are runtime-contained beneath `.prodkit/workflows/`; full-history Gitleaks produces redacted evidence and supports repository-contained reviewed allowlists; release-manifest v1 is strictly shape-validated; and consumer release output is rejected if it is empty, nested, symlinked, or attempts to overwrite central proof/source/SBOM artifacts. Contract tests lock these guarantees to `docs/CONTRACTS.md`, bootstrap output, local validators, generated caller routing, and reusable workflow behavior. Stable required-check identities remain `ci / CI Required` and `security / Security Required` across runner failover.

Release publication and release-presentation repair have deliberately separate trust boundaries. Publication requires the requested source SHA to be current `main` with successful exact-SHA CI/Security evidence and owns tag/artifact creation. Metadata repair is valid only for an already-published immutable tag: it uses current `main` solely as the canonical title/notes source, proves the tag still resolves to the supplied historical source SHA, verifies the complete published checksum set, changes only GitHub Release `name` and `body`, and re-verifies that tag identity, publication flags, asset identity, and payload checksums are unchanged.

The workflow surface is intentionally layered rather than one-to-one: `.github/workflows/` contains 9 YAML files (4 operator-facing workflows plus 5 reusable implementations), the generated consumer adapter catalog contains 11 shell adapters, and this control-plane repository itself enables only 4 `.prodkit/workflows/` adapters. Disabled capabilities do not require local adapter files; enabling a capability makes its configured adapter mandatory and runtime-validated.
