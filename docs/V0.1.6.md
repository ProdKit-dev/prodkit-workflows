# ProdKit Workflows v0.1.6

`v0.1.6` closes the private-repository runner gap discovered while exercising the complete v0.1.5 automatic release lifecycle from a consumer repository.

## What changed

- The normal proof dispatcher now runs on the configured trusted runner (`PRODKIT_RUNNER_JSON`) instead of assuming that GitHub-hosted `ubuntu-latest` capacity is available.
- `Trusted Release Proof` remains `workflow_dispatch` only and exact-source bound, but the default lifecycle now contains a separate `promote proven release` job that depends on successful proof completion. This serializes proof -> promotion without polling while another workflow needs the same single runner.
- The bounded GitHub-hosted proof observer from v0.1.4/v0.1.5 remains available as an explicit compatibility mode through `PRODKIT_GITHUB_HOSTED_CONTROL_PLANE=true`.
- `Release Promotion`, Release verification dispatch, Branch Cleanup, and Post-Gate Branch Cleanup use the configured trusted runner by default, removing hard dependencies on GitHub-hosted control-plane capacity.
- Organization audit now validates the trust and trigger invariants of both serialized and hosted-observer operation instead of hard-coding one runner class.
- Audit policy now accepts repositories that strengthen the permanent release-gate set beyond `CI` + `Security` (for example by adding `CodeQL`) while still requiring exact-source gate handoff.
- Release Verification audit semantics now match the shipped cleanup architecture: verification may hold `actions: write` to dispatch canonical cleanup, but must remain `contents: read` and cannot delete refs directly.

## Trust model

The runner change does not move release authority into consumer code. Exact-main permanent gates remain mandatory. Trusted Release Proof still validates the exact source and builds the promotable payload once. Promotion continues through the central `reusable-release-promote.yml` contract, publication through `reusable-release.yml`, verification through `reusable-release-verification.yml`, and destructive branch mutation through `reusable-branch-cleanup.yml` only.

The serialized default also preserves the single-runner non-blocking rule: no job dispatches another workflow that needs the same runner and then waits for it. Proof finishes and releases the runner before promotion begins.

## Compatibility

Existing consumers pinned to v0.1.5 remain unchanged. New or migrated consumers should pin the immutable v0.1.6 release commit and use the generated caller family as one coherent lifecycle. `PRODKIT_GITHUB_HOSTED_CONTROL_PLANE=true` is optional and should be set only when GitHub-hosted control-plane execution is deliberately available and desired.
